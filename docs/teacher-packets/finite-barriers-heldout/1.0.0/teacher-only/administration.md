# Real classroom administration and teacher review

**Unreviewed protocol and forms. Actual teachers and students must perform the steps below. No completed classroom study is represented.** A teacher must first check syllabus fit, scientific content, accessibility, timing, consent/data handling and institutional requirements. Keep teacher keys privately distributed; the repository's file separation does not make an assessment secure by itself.

## Before any student response

1. A real physics teacher reviews the sources, independent derivations, reference outputs and eight criteria. Record reviewer identity, date, decision, affected files/questions and reasons. A developer's numerical check is not that approval. If any file changes, increment the packet version and produce new digests before administration.
2. Decide whether the full eight-question form or the four-question common core fits the taught material. HP3–HP5 include transfer/extension cases beyond the runtime calculator's scope; do not unexpectedly assess untaught material as a prerequisite deficit. Pilot timing with actual learners before fixing the final duration.
3. Fix form allocation/order, intervals, permitted aids, feedback timing, criterion coding, missing-data/exclusion rules and the handling of technical failures. Record the chosen design before examining outcomes. Alternate forms have not been equated; record any counterbalancing and analyze by form rather than assuming equal difficulty.
4. Record packet/version/manifest digest, code build, runtime package reference, actual model alias/returned identity where available, prompt/configuration, source versions and evaluator versions. Keep provider credentials out of records. Use distinct roster identities and pseudonymous analysis IDs with a separately protected linking file.
5. Check actual student exposure to this public repository and any review archive. `teacher-only` filenames do not restrict access or establish blinding. Withhold keys, use fresh privately controlled equivalent questions where necessary, and preregister exposure exclusions. Record this check and any replacement form's version and digest before collecting outcomes.

## Pretest and instruction

An actual student completes the assigned first form before instruction and feedback. Collect and timestamp the original answers and confidence, plus permitted/observed assistance. If a question is unanswered, retain that fact; do not generate an answer or an explanation on the student's behalf. A teacher records any observed assistance; the app cannot establish whether external help occurred.

Teach the intended lesson using published/reviewed course materials and the deterministic policy. Preserve initial predictions, individual interventions, exact subsequent responses, teacher decisions and technical incidents. Log which reference results or model feedback were actually shown and when. Do not give a heldout question or key to the model to tune a prompt and then count it as independent validation.

## Immediate and delayed assessments

Give the alternate immediate form under the predeclared aid/time rules. Preserve the first submitted form before any feedback. Any subsequent correction is a dated revision linked to the original response and the actual feedback exposure. A task-correlated first answer while app help is locked counts as a valid independent submission condition; it may still contain no answer, a wrong number or an incorrect explanation.

At the agreed 7–14 day interval, give the remaining alternate form under comparable independent conditions. Record elapsed days, attendance, additional instruction, outside practice/help and departures from the planned conditions. A student absent from the delayed test remains missing, not a fabricated zero or improvement. If the teacher changes the interval, aids, questions or scoring, retain the change and analyze the affected records separately.

## Review and disagreement

For each question, a real teacher checks the actual student text against the specific criterion and writes a reason citing a line or equation. Record numeric correctness separately from explanation quality. Use `not_assessed` when the available answer/reference cannot support that judgment. If a second independent rater is available, preserve both ratings and reasons before adjudication; report agreement and disagreements with the sample size and the coding rule. Do not invent a second rater or teacher agreement statistic.

A reviewer may confirm performance on a named task/criterion, request revision, or ask a concrete prerequisite probe. Confirmation is not equivalent to broad long-term mastery. An app loop ending, a successful transport/schema check, a correct reference computation, a valid independent submission and a teacher-reviewed physical explanation are distinct observations. A new question or changed teacher action should link back to the review and reason that caused it.

The runtime `assessment_evidence` fields describe these boundaries: `valid_independent_submission` reports first locked task correlation; `numeric_correctness` reports only the scoped number check; `explanation_assessment` reports a task-specific model inference where available; `mastery_status=not_assessed` prevents those automated facts from being rebranded as demonstrated mastery. Actual attributed teacher rubric judgments remain separate review records. Historical records without that metadata remain unassessed; do not backfill it from a legacy `verified` flag.

## Analysis and reporting

Use one row per actual student, occasion and criterion, linked to its original answer, task/form/version, conditions, numeric check, explanation rating, reviewer and reason. Retain interventions and revisions as separate linked rows. Include assessment-status missingness, first-attempt and post-feedback outcomes, model/technical failures, attrition and form allocation. Exported JSON hashes detect file changes; they do not authenticate a teacher signature or prove that testing conditions were independent.

Report observed counts/distributions and paired descriptive differences only after real data exist. State how students/classes were selected, what comparison was used, whether allocation was randomized and what was missing. Without an appropriate comparison and design, do not attribute differences to the system; without reviewed delayed evidence, do not claim retained mastery. A small pilot is a feasibility exercise with uncertainty, not proof of educational effectiveness or competition approval.

No section in this packet is a place to prefill results. Blank fields and unperformed checks must remain visibly unperformed until real participants and reviewers provide the corresponding evidence.
